# ClassWatch 浏览器课堂监督系统

## AI Agent 开发执行文档 v1.0

> 本文档是项目第一阶段的产品需求、系统架构、技术约束和 AI Agent 执行规范。
>
> AI Agent 应严格按照本文档逐阶段实现，不得自行将系统改造成传统会议软件，不得擅自增加学生密码、学生注册、聊天、录屏、文件传输等未定义功能。

---

# 1. 项目目标

ClassWatch 是一个完全基于浏览器运行的远程课堂监督系统。

主要使用场景：

* OJ 算法训练监督
* 远程编程课堂
* 自习监督
* 课堂练习监督
* 教师观察学生电脑桌面
* 教师与指定学生进行私密语音沟通

学生不需要安装任何客户端。

支持：

```text
Windows/macOS
       │
       ▼
Chrome / Edge
       │
       ▼
ClassWatch Student Web
       │
       ├── Entire Screen
       ├── Optional Camera
       └── Optional Microphone
              │
              ▼
           WebRTC
              │
              ▼
         LiveKit SFU
              │
              ▼
      Teacher Web Console
```

核心原则：

> 学生必须持续共享完整显示器，才能处于正常课堂状态。

摄像头和麦克风不是进入课堂的必要条件。

## 2.2 学生账号

学生：

* 不允许注册
* 不设置密码
* 登录只输入账号
* 账号只能由管理员创建
* 停用账号后不能登录
* 学生不能创建其他学生
* 学生不能修改角色
* 学生不能查看其他学生资料

登录：

```text
Student URL
    ↓
输入 account
    ↓
账号存在且 ACTIVE
    ↓
登录成功
```

这是业务需求，不得擅自增加：

```text
❌ 密码
❌ 验证码
❌ 邮箱验证
❌ 手机号验证
❌ 注册页面
```

注意：

这种设计意味着：

> 知道学生账号的人理论上可以冒充该学生。

这是 V1 明确接受的业务安全模型，不属于实现 Bug。

但仍必须实现：

* IP/API Rate Limit
* Session 管理
* Disabled account 检查
* Classroom authorization
* Server-side RBAC

# 5. 三套独立 Web 入口

生产环境目标：

```text

admin.example.com
```

开发环境允许：

```text
localhost:5173   student
localhost:5174   teacher
localhost:5175   admin
```

推荐三个 Vue SPA：

```text
apps/
├── student-web/
├── teacher-web/
└── admin-web/
```

而不是：

```text
一个页面
if role == teacher
    show teacher UI
else
    show student UI
```

三个 Web 应用可以共享：

```text
packages/
├── ui/
├── api-client/
└── shared-types/
```

这样既保证产品上的入口完全分离，又避免复制大量公共代码。


# 16. 强制完整显示器共享

调用：

```javascript
navigator.mediaDevices.getDisplayMedia(...)
```

应用应该表达：

```text
prefer monitor
include monitor
avoid surface switching
```

但是必须理解：

浏览器最终仍然允许用户选择：

```text
monitor
window
browser
```

因此真正的业务 Gate 是：

```javascript
const track = stream.getVideoTracks()[0];
const settings = track.getSettings();

if (settings.displaySurface !== "monitor") {
    track.stop();
    rejectJoin();
}
```

如果：

```text
monitor
```

通过。

如果：

```text
window
```

拒绝。

如果：

```text
browser
```

拒绝。

如果：

```text
displaySurface == undefined
```

严格监控模式同样拒绝。

提示：

```text
当前浏览器无法确认你是否共享了完整显示器。

请使用系统支持的最新版 Chrome 或 Edge。
```

# 19. Server 端不能真正证明 displaySurface

必须明确威胁模型。

`displaySurface === monitor` 是浏览器客户端检查。

Server 可以验证：

```text
学生是否发布 ScreenShare Track
```

但 Server 无法获得一个不可伪造的密码学证明：

```text
“这个 Track 一定来自完整物理显示器”
```

所以：

ClassWatch V1 防御的是：

```text
正常用户误选 Tab
正常用户故意选择单窗口偷懒
停止屏幕共享
切应用
普通课堂逃避监督
```

它不是：

```text
高对抗型国家考试防作弊系统
```

一个主动修改前端代码、自己实现 WebRTC Client 的攻击者不在 V1 threat model。

AI Agent 不得在产品文档中宣传：

```text
100% 防作弊
绝对无法绕过
```

# 20. 发布 Screen Track

```text

        ↓
```

# 26. Student 之间隔离

产品要求：

```text
Student A
    ✗ Student B

Student B
    ✗ Student C
```

学生端：

* 不展示参与人数
* 不展示其他学生
* 不展示其他学生姓名
* 不订阅其他学生 screen
* 不订阅其他学生 camera
* 不订阅其他学生 microphone

LiveKit identity 必须使用 UUID。

即使底层 SDK 暴露 participant identity：

```text
2c81a...
8d917...
```

也不得包含：

```text
zhangsan
student001
手机号
姓名
```

媒体发布后应使用 Subscription Permission：

```text
Student media
     │
     └── Teacher allowed

Other students
     └── denied
```

同时 Student Client：

```text
autoSubscribe = false
```

只允许订阅经过业务逻辑确认的 Teacher Audio。

注意：

在共享同一个 SFU Room 的架构中，“互不感知”主要是产品和媒体权限层隔离，不定义为对恶意自定义客户端的协议级匿名性。

# 48. 打开 Classroom


Backend Transaction：

```text
1. SELECT classroom FOR UPDATE

2. verify owner

3. verify status == CLOSED

4. create ClassroomRun

5. generate opaque LiveKit room name

6. classroom.status = OPEN

7. classroom.current_run_id = run.id

8. commit
```

之后 Broadcast：

```text
ROOM_OPENED
```

学生 Dashboard 自动更新。

# 85. 最终产品边界

ClassWatch V1 的目标不是：

```text
腾讯会议 Clone
```

也不是：

```text
专业 LockDown Browser
```

它是：

```text
Browser-based Classroom Supervision Platform
```

核心价值只有三个：

```text
① 老师控制谁能进入哪个课堂

② 学生必须持续共享完整 Display

③ 老师能够同时监督多个学生并与指定学生沟通
```

所有设计优先服务这三个目标。

任何新增功能如果不能明显服务核心目标：

```text
不要加入 V1。
```
